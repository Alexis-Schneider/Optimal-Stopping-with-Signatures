# Optimal Stopping with Signatures

**Numerical study and implementation of Bayer, Hager, Riedel & Schoenmakers (2021), *Optimal Stopping with Signatures*, [arXiv:2105.00778](https://arxiv.org/abs/2105.00778).**

Supervised research project carried out under the supervision of **Prof. Sergio Pulido** (LaMME, ENSIIE — Université Paris-Saclay), as part of a broader study of signature methods and deep learning approaches for American-type option pricing under rough (non-Markovian) dynamics.

Author: Alexis Schneider (ENSIIE).

## Problem

The goal is to compute the value of an optimal stopping problem

$$V^* \;=\; \sup_{\tau \in \mathcal{S}} \mathbb{E}\big[Y_{\tau \wedge T}\big],$$

where the reward $Y$ is adapted to the filtration generated by a stochastic process $X$ — financially, the price of an American option. Classical numerical methods (dynamic programming, Longstaff–Schwartz, Deep Optimal Stopping) rely on $X$ being Markovian. The paper removes this assumption entirely: $X$ only needs to be a continuous **geometric random rough path**. This covers fractional Brownian motion with $H \neq 1/2$, which is neither a Markov process nor a semimartingale, as well as rough models for electricity spot prices.

## Method

The implementation follows the three building blocks of the paper:

1. **Randomized stopping times** (Section 4). Stopping decisions are encoded by a continuous intensity $\theta$ acting on the stopped path, with stopping triggered when $\int_0^t \theta^2 \, \mathrm{d}s$ crosses an independent $\mathrm{Exp}(1)$ threshold. This makes the expected payoff differentiable in $\theta$ (Prop. 4.4) without changing the optimal value (Prop. 4.2), enabling gradient-based optimization.

2. **Signature stopping policies** (Sections 5–7). The policy is a functional of the signature of the time-augmented path $\hat{X}_t = (t, X_t)$:
   - *linear policies* $\theta_l = \langle l, \hat{X}^{\le N} \rangle$ on the full signature (Prop. 5.5), which exploit the shuffle identity and lead to a deterministic optimization over the expected signature;
   - *deep policies* $\theta_{\log} \circ \log^{\otimes} \hat{X}^{\le N}$, a feed-forward network on the truncated **log-signature** (Thm. 1.2 / Prop. 7.4). The log-signature is a compressed, non-redundant representation whose dimension $\eta_{d,N}$ (Witt formula) is independent of the time discretization.

3. **Monte-Carlo training and low-biased evaluation** (Section 8, Appendix C). The smooth loss of Prop. 4.4 is minimized with Adam over simulated trajectories; the trained policy is then re-evaluated on fresh out-of-sample paths, yielding a low-biased estimate of $V^*$.

## Experiments

The notebook reproduces the two numerical examples of Section 8. All estimates below are low-biased, out-of-sample Monte-Carlo values (95% confidence intervals), computed on $2^{17}$ fresh paths.

| Experiment | Policy | This implementation | Reference (paper) |
|---|---|---|---|
| Optimal stopping of fBm, $H = 0.1$, $J = 100$ | Deep log-signature, $N = 2$ (3 features) | **1.024** ± 0.005 | 1.030 (Table 2) — BCJ'19: [1.048, 1.049] |
| Optimal stopping of fBm, $H = 0.1$, $J = 100$ | Linear signature, $N = 3$ | **0.738** ± 0.004 | 0.760 (Table 2) |
| American put on rough electricity spot, $K = 100$, $\alpha = -0.4$ | Deep log-signature, $N = 2$ | **18.214** ± 0.050 | 18.279 (Table 3) |
| European put (control), $K = 100$ | — | **5.749** | 5.770 |

Two remarks, consistent with the paper's findings:

- the **deep log-signature policy with only 3 features** approaches the benchmark of Becker–Cheridito–Jentzen (2019), which requires a 100-dimensional Markovian lift of the path — the log-signature acts as an extremely efficient compression;
- the **linear method underperforms** at every truncation level, as the shuffle-exponential truncation error dominates the optimization (Section 8.1).

Sample sizes are calibrated to run on a laptop CPU in minutes ($2^{16}$ training paths for the deep policies, versus $2^{21}$ in the paper), which accounts for the small remaining gaps to the reference values. The European put price, computed as a model-validation control, matches the paper's value to within Monte-Carlo error.

## Installation

```bash
pip install numpy scipy matplotlib torch signatory
```

`signatory` ships pre-compiled against specific PyTorch versions; if the plain install fails, pin a matching pair, e.g.

```bash
pip install torch==1.9.0
pip install signatory==1.2.6.1.9.0
```

(See the [signatory compatibility table](https://github.com/patrick-kidger/signatory).) The notebook pins BLAS/OpenMP to a single thread before importing `torch`, which avoids known CPU deadlocks in signatory's C++ extension.
